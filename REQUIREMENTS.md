This table maps every requirement from the project brief to the code and tests that
satisfy it. Rows marked *planned* point to the phase that will deliver them.
Updated at the end of every phase.

## Non-functional requirements

| Quality | Requirement | Where it is covered |
|---|---|---|
| Usability | Main actions within 2 clicks of the dashboard, no manual needed. | `templates/base.html` header + sidebar (`app/navigation.py` builds the menu per role); both dashboards link straight to each action. Phase 2: My Profile is one click from the sidebar or the dashboard card; Edit, Change Password and Change Photo are one more click. Phase 3: Manage Activities, Manage Locations and Volunteers are one click from the sidebar (or from the dashboard stat cards); New / Edit / Delete / status change / Deactivate / Reset password are one more click, each destructive action behind a `confirm()`. Phases 4-8: Activities, My Registrations, My Schedule, Notifications, Registrations, Reports and Audit Logs are one click from the sidebar; Register / Cancel / Approve / Reject / Download CSV / Printable view are one more click. Phase 9: skip-to-content link, `<main>` landmark, `aria-expanded` sidebar toggle that closes on Escape, loading state on submitted forms, labelled fields with inline errors, text status badges, one `h1` per page, horizontally scrolling tables, empty states everywhere, error page hints per code; `tests/e2e/test_accessibility.py`. |
| Reliability | Full 15-minute demo without unhandled crashes. | Typed errors + global handlers (`app/__init__.py`); reconnect in `DatabaseManager.connection()`; row locks on every registration write so the demo cannot over-book; `docs/DEMO.md` is the scripted 15-minute walkthrough with recovery steps, `python seed.py` gives it data in every status (`tests/integration/test_seed.py`); 532+ unit/integration and 12 browser tests run in CI on every pull request. |
| Performance | CRUD on 1,000 records within 2 seconds. | Indexes on every FK and on `activity_date`, `status`, `title`, `timestamp` (`database/schema.sql`); `LIMIT/OFFSET` pagination in `ActivityDAO.search()` and `UserDAO.search_volunteers()` (shared `Page` class in `app/services/pagination.py`); the browse page (`/activities`, Phase 4) never loads the whole table: `ActivityDAO.search()` fetches 12 per page and `count_search()` runs one `COUNT(*)` with the same WHERE clause; `LocationDAO.list_with_activity_counts()` gets every count in one LEFT JOIN query; `python seed.py --big` creates 1,000 activities for the check, and `tests/integration/test_browse_flow.py::test_pagination_splits_13_activities_and_links_keep_filters` proves the page math. |
| Security | No plain-text passwords; all SQL parameterized. | bcrypt cost 12 in `app/auth/passwords.py`; every DAO uses `%s` placeholders (`tests/unit/test_dao.py::test_user_dao_insert_sets_id_and_binds_values` proves injection text stays a parameter); `Person.to_dict()` strips the hash. |
| Maintainability | Modules: models, views, controllers, dao, database; PEP 8 naming. | Folder layout in `README.md`; `ruff` enforces PEP 8 (`N` rules) and `mypy --strict` checks types in CI. |
| Portability | Runs on any machine with Python 3 and XAMPP via the README; no hard-coded paths. | All settings come from `.env`; `scripts/init_db.py`, `scripts/tailwind.ps1` and `scripts/screenshots.py` use relative paths; `docs/DEPLOYMENT.md` covers the XAMPP setup and a small production install (dedicated DB user, WSGI server, HTTPS, backups). |
